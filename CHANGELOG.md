# Changelog

What changed, written for whoever reads it next — and increasingly that is a
model opening this repository with a fortnight-old memory of it.

So this is **not a list of what shipped.** `git log` is that, and is better at
it. Each entry carries one line a person can scan, and behind a fold, the
statements that **were true and are not any more**: the branch that stopped
existing, the default that moved, the refusal that became a capability. Those
are the sentences that turn a confident wrong answer into a correct one, and no
tool can derive them from a diff — so a person or a model writes them, in the
pull request that made them true.

Unreleased work lives as one file per pull request in
[`docs/changes/unreleased/`](docs/changes/unreleased/) and is rolled up here when
a version is cut. [`docs/rules/changelog.md`](docs/rules/changelog.md) is the
rule.
