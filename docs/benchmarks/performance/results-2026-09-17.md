## Startup

Cold start is best-of-20 for `--version`. First frame is time to the first non-blank
character painted in a 160x48 pane, on an authenticated profile, in the repository, with any
folder-trust dialog cleared first.

| CLI | cold start | first frame |
| --- | --- | --- |
| codex | **5–7 ms** | **131 ms** |
| claude | 8–11 ms | 572 ms |
| **CodeAF** | **12.5 ms** | **208 ms** |
| cursor-agent | 306–479 ms | 1,298 ms |
| opencode | 314–352 ms | 2,420 ms |
| pi | 330–360 ms | 398 ms |
| omp | 337–387 ms | 400 ms |

**codex is faster than CodeAF on both**, by about 2x on cold start and 1.6x to first frame.
Both are single static binaries; the remaining gap is package init, of which about 7.3 ms is
one dependency's lexer registry parsing its embedded definitions before `main`.

## Startup work

`strace -f -e trace=openat,connect,execve` over `<cli> --version`, the same command for
every CLI, invoked directly with no wrapper process.

| CLI | `openat` | succeeded | `connect` | `execve` |
| --- | --- | --- | --- | --- |
| **CodeAF** | **15** | 13 | **0** | **1** |
| codex | 16 | 14 | 0 | 1 |
| claude | 30 | 27 | 0 | 1 |
| opencode | 45 | 39 | 0 | 1 |
| omp | 86 | 79 | 0 | 2 |
| cursor-agent | 363 | 355 | 18 | 18 |
| pi | 1,581 | 1,481 | 0 | 7 |

15 against codex's 16 is a tie in everything but arithmetic. Five of the seven open no
network connection to print a version; cursor-agent opens 18, nine of them to the network,
and runs 18 processes.

## Where this table has been wrong before

An earlier version of the startup-work table gave CodeAF 54 opens and 3 execs, and other
CLIs up to 6,024 opens and 252 network connections. Those numbers are withdrawn: the script
that produced them traced CodeAF as a full interactive boot while tracing the others as
`--version`, and wrapped every CLI in `env`, which added a phantom `execve` to every row.
The error ran against CodeAF and the correction favours it, which is the reason to record
the correction rather than quietly replace the figures.
