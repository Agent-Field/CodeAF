$ aforge plan run --help
  aforge plan run <plan.json> [--dir dir] [--parallel 8] [--out done.json] [--yes-spend]
                       [--model slug] [--plan-model slug]
                         the by-hand pipeline: a plan written to a file, then executed
                         exactly as written. It is not what most people want — nothing
                         it learns mid-flight can change a plan that is already frozen.

flags:
  --dir string
      the directory to work in (default ./aforge-<goal hash>)
  --max-turns int
      runaway backstop on iterations per step (clamped to the executor's own
      backstop) (default 200)
  --model string
      work model for this run (flag › AFORGE_MODEL › crew › default)
  --no-method
      do not write a working method for each step before running
  --out string
      write the completed plan as JSON to this file
  --parallel int
      how many steps may run at once (default 32)
  --plan-model string
      model for instructions, working methods, and recalibration, when different
      from the work model (flag › AFORGE_PLAN_MODEL › crew mastermind ›
      the work model)
  --token-budget int
      token budget per step — the limit that actually binds (default 150000)
  --total-token-budget int
      token budget for the whole run; once passed, nothing new starts and steps
      in flight land (0 = per-step budgets only)
  --yes-spend
      spend past today's limit and past the plan-price question, without
      stopping to ask

$ aforge run --help
  aforge run  <program> --input <file.json|-> [--dir dir] [--model slug] [--journal path]
                       [--json]
                         run one saved program, with nobody watching: typed input in,
                         its account and its typed output on stdout, everything else on stderr
                         a question it was not told how to answer stops it rather than being guessed
                         exit 0 done · 1 could not be run at all · 2 ran and did not finish · 3 a limit you set stopped it · 4 needed an answer and nobody was there
                         the three differ by how much thinking happens before the work starts:
                         do plans and may split the job, exec does not plan, run follows a
                         plan somebody already saved

flags:
  --dir string
      the directory to work in, edited in place (default: the current directory)
  --input string
      the typed input, as a JSON file — "-" reads it from what is piped in
  --journal string
      keep an account of every call this run makes in this file, one JSON object
      per line
  --json
      print one machine-readable object instead of the answer: ok says whether
      the work stands, stop says why it ended, answer carries what was produced,
      files what it wrote, and error the sentence when it could not be run at
      all
  --model string
      work model for this run (flag › AFORGE_MODEL › crew › default)
