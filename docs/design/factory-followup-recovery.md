# Follow PR recovery

Verification retains every attempt but accepts corrected Cargo invocations by scope. The scope includes checkout, target and measured execution context. Replacing an invalid multi-filter command requires successful coverage of all named tests on the current checkout; narrower or unrelated checks cannot satisfy it. Intentional regression failures are superseded only by adequate passing checks on the repaired checkout. Other tools keep conservative exact identities.

Follow PR retries can import a saved checkpoint of currently passing receipts into their new conversation. Original journals remain untouched. This reuses evidence, not the execution or cost of previous commands, commits or pushes. Any outstanding failure, changed checkout or unknown result refuses the checkpoint. The latest feedback must still be assessed and a proper structured report submitted.

Review cursors use comment IDs and content revisions with GraphQL thread resolution. Outdated lines remain findings; resolution and diff movement do not create requests. A queued snapshot is acknowledged only after successful maintenance, so comments arriving during work remain pending. Incomplete reads cannot assert complete review handling.

A paused repair remains observed and exposes its monitoring status and pending feedback. New actionable feedback can wake eligible Auto execution pauses within the existing attempt/budget bounds. Stop, takeover, closed jobs and actual user decisions retain their control. The known legacy malformed-Cargo pause gets one compatibility recheck only after its saved current-checkout evidence passes the corrected guard and fresh authenticated PR facts arrive. This never accepts work or republishes it automatically.

Contributor agreement status remains a merge gate, shown as CLA pending. It is not a running test or something a coding agent can sign away. Recovery's reconnect window excludes time spent productively running an admitted attempt; retry count and actual waiting remain bounded.
