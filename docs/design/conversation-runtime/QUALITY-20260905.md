## An interface defect the benchmark misses

This standalone probe imports the real package types, with no `Any` escape:

```python
from typing_extensions import Never
from returns.interfaces.failable import FailableN
from returns.validated import Invalid, Validated


def recover(container: FailableN[int, int, Never]) -> object:
    return container.lash(lambda error: container.from_value(error + 1))


value: Validated[int, int] = Invalid((1, 2))
print(recover(value))
```

The callback promised an integer receives a tuple. Checking the entire source
and probe together with incremental checking disabled confirms the imports are
resolved: mypy accepts all 119 source files, but execution raises `TypeError`.
The candidate suppresses incompatible interface overrides; green type checking
alone therefore does not establish substitutability.

The same runtime failure occurs in the benchmark's reference implementation.
Its full-source type check additionally reports three errors in two files.
This is a benchmark coverage limitation, not evidence that Aforge alone introduced
this kind of defect. These supplemental probes do not rewrite the frozen score.

The committed supplemental check is `bench/deepswe/validated-contract.py`.
It requires both rejection of an incompatible caller and successful type checking
and execution of a compatible caller, alongside clean library source checking.
It fails for both frozen Validated implementations. A control using the existing
Result implementation passes all four conditions, including rejection at the
negative call site. These controls run without network or model calls.

## Runtime fixes and remaining work

The current wave repairs task opening and transcript refresh, missed deadlines
while workers are silent, malformed shell arguments becoming unreadable permission
cards, and false switching status when no second model request starts. Automatic
routing now carries declared verification commands through the existing task
contract. Changed requests, composed commands and partial handoffs do not acquire
execution rights from stale or whole-request checks. Worker receipts remain
evidence, not permission to repeat arbitrary commands.

Kept-branch completion messages now tell the parent to inspect and test the work
there and preserve the requested branch and review workflow. The protected-branch
sentence no longer invites an unsolicited merge or claims shell access cannot
change that branch. This is guidance to the model, not a general Git restriction;
live compliance remains to be established. Real repository tests cover the kept
branch and inconclusive-review paths. The final session/manual make-check passes
(185.713 and 1.982 seconds), with vet, formatting, packed manual, build and size.

Task workers and short forks already instantiate the same Agent core. The simpler
direction is to retain one owner and one request, use ordinary tools directly,
and give independent work a child only when useful. Further nested tool managers
would not fix the observed failures. Overlapping handoff/routing policies remain
a consolidation target after behavior is dependable.

Still required before a production claim:

- Preserve the user's branch/review instructions through task completion and
  parent follow-up; validate actual behavior on a live run.
- Exercise public interface contracts beyond happy-path acceptance tests, without
  blanket typing suppressions, and add more substantial repository cases.
- Repeat end-to-end work on the corrected verification handoff, including failure,
  cancellation, correction and recovery paths.
- Verify the updated terminal build in the user's actual task. That existing
  terminal has not been restarted or changed by this work.
