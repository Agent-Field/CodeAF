Apps · read me first
The build spec for Apps in CodeAF. Self-contained: if you never saw the design conversations, start here, then the model (S-A1), then the band you are building.
An app is a small piece of software that lives inside CodeAF: records , screens , runs and its own agent , all written as plain files. You say what you need in plain words; Builder , CodeAF's own agent, shows a plan, writes the files, checks them and shows the app running on sample data. You keep it and work in it in a tab ( Use ). Editors change it later in Shape : a private draft of the running app that becomes the next version for everyone on Apply . Every app runs on a codeaf server, either your own ( Personal ) or your company's ( Workspace ), and is built from the same 59-part kit, so every app looks and behaves like CodeAF. The running example on this page is the CRM in the acme workspace.

Glossary one meaning per word · use exactly these words in UI, code and docs
Word Means Spaces and people App Records, screens, runs and an agent, described in plain files and run by a codeaf server. A row in the rail's Apps section. Personal app or Workspace app , by its space. Space One codeaf server and everything on it: apps, records, runs, connections. Personal or a workspace. Personal Your own space: a codeaf server inside your desktop app. Only you, your own accounts. You hold every role. Workspace A space a company or team runs on its own codeaf server (the same binary, self-hosted). Members are invited by an Admin. One person can be in several: Personal · acme · globex. Roles Workspace: Owner · Admin · Member . App: Editor · User · Viewer . Signatories (e.g. “Quality lead” ) sign SignOff chains; they grant nothing else. Making and changing Builder CodeAF's own agent, the same for every app. Writes the app's files. Appears in the plan card, Building and Shape. Never reads content. Plan card CodeAF UI drawn from plan.json : Data · Automation · Screens · Agent · Needs. Every line editable in place. Write it · Just build it · Change plan. Check Schema check · kit law · every screen rendered with sample data · runs executed on sample data against fakes. Fail → back to the Builder, max 3 rounds, then Fix it · Cancel.
Word Means Making and changing Shape The header mode for changing the app, Editors only. Left plan menu · centre your draft · right Builder · top draft bar. Draft Your private copy of the running app in Shape. Reads real records, writes to a scratch copy ( “reads real data · saves to a scratch copy” ). Stored as your requests + the diff. Apply Turns your draft into the next version for everyone ( “everyone in acme gets v2” ). One Activity line: “Mona shaped CRM · v12 · View · Undo” . Version A numbered state of the app's files: v1, v2… v1 is private to its maker until the first Apply. Any version can be restored from Versions… Replay Someone applied first: the Builder runs your stored requests again on the new version. “Your request was replayed on v13” . Migration preview Shown before Apply when a field is changed, renamed or removed: “38 deals affected · nothing deleted” . Using Use The header mode for working: the app's screens with the app's agent docked. App agent The app's own agent ( “CRM agent” ), defined by agent.md . Content only. Asked to change the app it answers “That changes the app” + Shape this . Ask · Nudge · Comment Three ways to change a part: Ask the app agent · Nudge a small edit by hand (words, drag a box) · Comment pinned to an element, for the agent or a person.
Word Means Data and running Records The app's data, typed by the schema in app.json , stored on the space's server. Record rules Freeze (lock a period or a record) · Blind fields (hidden until you submit) · Computed fields (from time or other fields). Enforced by the server. Runs Automation from runs/*.yaml on the runs engine: steps, loops, gates, waits, retries, a budget per run. Only runs touch shells. Surfaces The one hard editing part of an app: Text · Canvas · Grid · Timeline · Graph · Map. Content is plain files. Parts The units of a surface: a slide, a section, an artboard, a sheet. One writer at a time, presence, versions per part. Needs What an app is allowed to do (record types, connectors, approvals, AI, budget), computed by CodeAF from the files. Shown in the plan card and App ⌄ → Needs. Connectors Connectors Personal : yours (your Gmail, Calendar…), travel with you; a workspace app acts as you only after you Allow it, once per app. Workspace : belong to the workspace (support@, Stripe, GitHub org); only Admins add or remove them. Fake connector The dry-run double every connector has. Used in Preview, Shape drafts and checks. Nothing real is sent before Apply.

Ten rules you never break each is enforced in code, not by the UI alone
01 The Builder never reads content. It sees the app's files, the kit, sample data and check results. Never records, content files, comments or real connector data.
02 The app's agent never changes the app. No writes to app.json , screens/ , runs/ , agent.md . Asked to, it answers “That changes the app” with the Shape this button, which opens Shape with the request pre-filled for the Builder.
03 Nothing leaves the workspace without approval. Every send, post, payment or external write waits on “Approval needed: …” (gate send ). No setting turns this off.
04 Drafts never write real records. A draft reads real records and writes only to its scratch copy. Its connectors are fakes. Real writes start after Apply.
05 Every bridge call is checked on the server against app.json. Record type, capability, connector and the caller's role, on every call. The client is never trusted, including the kit.
06 Screens use the kit and tokens only. screens/*.json names kit parts and bindings. No raw colours, sizes, fonts, fetch or network. custom/*.tsx runs sandboxed and is labelled “custom” .
07 Apply never loses data. A changed, renamed or removed field shows the migration preview first; nothing is deleted. Undo returns to the previous version.
08 An app acts as a person only with that person's Allow. Once per app, per person: “CRM may send email as Mona · Allow · Not now” . Workspace connections are added only by Admins.
09 AI is always labelled, and people win. Any AI-set value shows “· AI” ( “Likely to close · AI” ). A pin or a person's edit always overrides it.
10 Runs run on a codeaf server, inside a budget. Yours or the workspace's, never in the UI. A run that would pass its budget stops and asks. Only runs touch shells.
