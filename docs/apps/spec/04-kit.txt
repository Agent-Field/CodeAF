L4 · The kit v2 · 59 parts
We build six surfaces once. Every app is easy parts (lists, forms, approvals) plus one surface, the hard editing part; there are no app-specific blocks. The Builder (CodeAF's agent) writes declarative screens, screens/*.json , that name only kit parts and bind them through the bridge; custom/*.tsx is a sandboxed escape hatch. The app's agent works on content only. v2 closes the gaps found by the 14-app gallery (L7, L8). Everything here is live HTML on CodeAF tokens.

Bridge the one door between screens and the shell @codeaf/bridge
Hooks read · live · bound in screens/*.json useRecords(type, query) Live list of this app's records; counts per state come from the shell. useRecord(id) One record with fields, links, history. Another app's record is read-only , via a link. useParts(file) A surface file split into parts, with lock, presence and versions per part. useRuns(query) · useRun(id) Runs, live: steps, rounds, gates, .log , .diff , .proof , .files . useAgent(name) The app's agent: state, spend vs budget. To talk to it, open() the pane. usePeople() Workspace members: handles, avatars, who is around, app roles (Editor · User · Viewer).
Actions ask the shell to act records.update(id, fields) Writes this app's records; every write has Undo. A removed field is hidden, never deleted. runs.start(name, input) · runs.stop(id) Starts a pipeline after the cost check (“up to $2”). Stop keeps its work. approve(kind, payload) Anything that leaves the workspace : “Approval needed: send email”. inbox.ask(question) A plain question in Inbox; the answer comes back to the caller. tools.call(server, tool, args) A connector declared in app.json . The only way out; no fetch . ai.sort · ai.summarise AI inside an app, always labelled “· AI”; a hand pin or drag wins. link(a, b) · open(record | agent) Links records across apps (other side read-only); opens a record or the agent pane.
Your records An app reads and writes its own records freely, with history and Undo.
Other apps Read-only through links. CRM shows a deal's Support tickets; it cannot edit them.
Leaving the workspace Goes through approve ; a direct tools.call('gmail','send') is refused.
Capabilities Each hook and action needs one in app.json ; adding one is a change you approve.
Kit law enforced by the checker before preview · a failure goes back to the Builder kit lint
Rule Checker rule Bad → good Screens name only kit parts screens/*.json is checked against the kit schema; custom/*.tsx imports only kit, bridge, react. kit/parts { "part": "DataGrid" } → { "part": "Table" } Hard editing uses a surface No hand-rolled editors; an app is easy parts plus one surface. kit/surface { "part": "custom/SlideEditor" } → { "part": "Canvas", "frame": "16:9" } No raw colours, sizes or fonts Tone, state and tokens; the theme does the rest. kit/no-raw-style "style": { "color": "#e5484d" } → "tone": "critical" No fetch, no network Connectors are declared and called through the bridge. kit/no-network fetch('https://api.hubspot.com/deals') → tools.call('hubspot', 'deals.list', q) One navigation row One SectionTabs per app, under the CodeAF header. kit/one-nav two SectionTabs in one screen → { "part": "SectionTabs" } once Lists that can grow use RecordList With QueryField, so search works the same everywhere. kit/record-list { "part": "List", "rows": "$deals" } → { "part": "RecordList", "type": "deal" } Destructive actions go through Dialog The label ends in “…”; the dialog names what ends and what stays. kit/confirm { "part": "Button", "do": "remove" } → { "do": "remove", "confirm": "Remove Globex?" } Anything leaving the workspace goes through approve Email, posts, replies to customers. kit/approve tools.call('gmail', 'send', mail) → approve('send email', mail) Every interactive element has a label Screen readers, tooltips and ⌘K use it. kit/label { "part": "IconButton", "icon": "more" } → + "label": "Deal actions"
