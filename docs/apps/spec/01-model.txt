Never by the app's agent. plan.json Builder JSON · plan/1.json New app and Shape; the plan card edits it in place (each edit is a request to the Builder). screens/*.json Builder JSON · screen/1.json Declarative tree of kit parts. One file per screen; file name = screen id. runs/*.yaml Builder YAML · run/1.json Runs engine pipelines. File name = run id. agent.md Builder Markdown Front matter: model, tools; body: the app agent's instructions. Read by the app agent only. custom/*.tsx Builder TSX · kit law Escape hatch. Rendered in a sandboxed iframe, labelled “custom” in Shape and the plan card. migrations/*.json CodeAF JSON · migration/1.json Generated from the app.json diff at Apply time; never written by hand or by AI. content files app agent · people per surface (below) Ask · Nudge · Comment. One writer per part (light lock). Each save = one commit. records.db codeaf server SQLite (modernc) Records, record history (every change: who, when, before, after), links, locks. The app's agent writes content files and records only . The Builder writes the definition only and never reads content or records. Personal apps live on your personal server; workspace apps on the workspace server; Move to workspace… copies the folder and records, then archives the old one.

Record rules
Rule In app.json Behaviour Freeze freeze: [{when}] or {period, field, after} Matching records become read-only for everyone, runs and agents included. Editors see Unfreeze… (Dialog, reason required, logged). except lists fields that stay writable. Blind blind: {until: "submitted", per} Each person sees only their own value until they press Submit ; after everyone in per scope submits (or an Editor closes the round), all values show. Agents never read blind values before that. Computed computed: "<expr>" Server-evaluated on write and on a 1-minute tick for time functions. Read-only, indexable, sortable. Shown with a small “computed” hint in RecordPage. Lookup tables go in the type's constants . AI field ai: "<question>" Filled by ai.sort on demand, never on write. Always labelled “AI” ( “Likely to close · AI” ). A person's value pins it: AI never overwrites a pinned value. Masked masked: true Value hidden as •••• until Reveal ; each reveal writes an audit line (who, record, field, when). Agents get the masked form.
Expressions · used in app.json, screens and runs
Queries QueryField tokens, the same text people type: stage:Proposal,Negotiation owner:me amount>10000 sort:-amount . - excludes, , = or, is: / has: flags, sort: and group: last. Compiled to SQL on the server [S-A3]. Conditions when and if use CEL (the subset: literals, fields, $ references, == != < <= > >= in && || ! , ?: , and the functions now() days_since() changed() count() records() me() ). Server: cel-go. Screen runtime: the same programs, compiled by the server and shipped with the screen; both run one shared test-vector file. Templates { { deal.name} } in strings (labels, prompts, confirm text). No logic inside braces. References $me · $space · $params.x · $record · $row · $selection.<listId> ( .ids , .id , .count ) · $input.x (values a Sheet asked for) · $steps.<id>.output (runs only) · $now .

Screen language screens/*.json · interpreted by the screen runtime, no code generated
A screen is a tree of nodes. Each node is one kit part. The runtime walks the tree, resolves bindings through the bridge, evaluates when , and renders kit components. The Builder writes the tree; nothing is compiled.
Node shape · {part, props, bind, on, when, children}
Key When Meaning part required A kit v2 part name ( RecordList , Button , Panel , Text …). Unknown name = schema error. Custom + src: "custom/x.tsx" loads the sandbox. id lists, forms Unique in the screen. Needed for $selection.<id> and for focus links ( open with focus ). props optional Static props from the part's prop schema (kit ships one JSON Schema per part). Strings may hold { { templates} } . No raw colours, sizes or fonts: token names only. bind optional Where the part's data comes from (table below). One binding per node; children inherit $row / $record . on optional Event → list of actions, run in order; the first failure stops the list and shows a Toast with the error. when optional CEL condition; false = node not rendered (not hidden: no DOM, no data fetch). children optional Ordered child nodes. Layout parts ( Stack , Row , Panel , Sheet ) take children; data parts take row / empty slots instead. label interactive Required on every interactive node (kit law); used for a11y and menus.
Bindings
Binding Shape Gives records {"records":"deal","query":"stage:-Lost"} Live list, paginated 100, server-sorted. QueryField and StateMeter in RecordList wire to it; people's query edits replace query for that view only. record id {"record":"$params.id"} One record, live. Missing → the part's Empty state “This deal was deleted · Undo” (for 30 s) or “Not found” . run {"run":"follow-up","for":"$record.id"} · {"runs":"follow-up"} A run's live state (RunTimeline, ApprovalCard) or the list of runs of that id. selection {"selection":"deals"} The current selection of list deals : rows, ids, count. Changes as people click. params {"params":["id","view"]} Values passed by open or the URL codeaf://acme/crm/deal?id=… . Declared on the screen root; undeclared params are dropped.
Actions · used in on lists, commands and BulkBars. Every action is checked against the app's capabilities on the server, not in the screen.
Action Shape Does Needs open {"open":"deal","id":"$row.id"} Opens a screen (in the card) or a record (in the panel). beside: true opens in a new tab. — records.update {"records.update":{"ids":…,"set":{…} } } Writes fields; one history entry per record; one Undo toast for the batch. records: rw runs.start {"runs.start":"follow-up","params":{…} } Shows the cost check first when the run has a budget ( “Run · up to $0.50” ). runs listed in app.json approve {"approve":"$run.gate","answer":"yes"} Answers a gate. Only the named approver; 5-second “Approving… Undo” . gate's who inbox.ask {"inbox.ask":{"to":"$record.owner","q":"…"} } Puts a question in a member's Inbox, linked to the record. — tools.call {"tools.call":["gmail","draft",{…}]} Connector or MCP tool. Outbound kinds (send, post, pay) become an approval instead of acting. connectors / tools ai.sort {"ai.sort":"deals","field":"likely"} Fills an ai field for the visible rows, labelled “AI” , pins kept. Costs from the app budget. ai: sort

runs/*.yaml the runs engine · journal-backed, durable
definition/runs/follow-up.yaml CRM
run : follow-up title : Follow up on stale deals budget : { per_run: 0.50 } # at the cap the run pauses as Needs you params : deals : { type: refs, to: deal, default : "stage:Qualified,Proposal,Negotiation last_touch<-14d" } steps : - id : each loop : { over: $params.deals, as: deal, max: 25 } steps : - id : thread tool : gmail.search # as the deal owner (allowed once per app) as : $deal.owner args : { q: "to:{ { deal.contacts.email} } newer_than:30d" } - id : draft agent : CRM agent prompt : Draft a short, plain follow-up for { { deal.name} } from the thread. retry : { max: 2, backoff: 30s } - id : send gate : { approval: send, who: $deal.owner } # Approval needed: send tool : gmail.send as : $deal.owner args : { draft: $steps.draft.output } - id : reply wait : { for: gmail.reply, thread: $steps.send.thread, timeout: 5d } on_timeout : continue - id : touch records.update : { id: $deal.id, set: { last_touch: $now } }
definition/runs/repro.yaml Support app · workspace: repo
run : repro budget : { per_run: 3.00 } steps : - id : plan agent : Support agent gate : { approval: plan, who: $ticket.owner } - id : fix workspace : repo # checkout, branch, shell on a runner repo : acme/api branch : support/{ { ticket.number} } loop : { until: "$steps.test.exit == 0", max: 3 } steps : - id : change agent : Support agent - id : test shell : go test ./... - id : pr gate : { approval: proof, who: $ticket.owner } tool : github.pr.create
Key Rule steps Ordered list; each step has a unique id and exactly one of agent · tool · shell · records.* · wait · nested steps . loop over: <list>, as, max (for each) or until: <CEL>, max (repeat). Shown as a parent row with rounds in RunTimeline. max required; hitting it → Needs you “out of rounds” . gate approval: plan | proof | start | send , who (person or role). The run waits in the journal; the approver gets “Approval needed: send” in the Inbox. Outbound tools always get a send gate even when the YAML omits it. wait for: <connector event> with a match, until: <time> , or for: 2h . Durable timer in the journal: survives server restarts. timeout + on_timeout: fail | continue . retry max (≤ 5), backoff (doubles each try, cap 10m). Retries only on step errors, never on a gate “No” . budget per_run in USD, counted from model and paid tool spend. Must fit the app's monthly budget; at the cap the run pauses as Needs you with Raise budget · Stop. workspace: repo The step (and its children) runs on a runner: fresh checkout of repo , branch , a shell. Only workspace: repo steps may use shell . Screens never touch shells. as $person acts with that member's personal connector (needs their per-app allow) · omitted = the workspace connection named in app.json. if · on_error if: <CEL> skips the step when false. on_error: stop | continue | goto <id> ; default stop.

Versions git under the hood · a version = request + diff + who
What a version is One Apply = one commit on definition/ tagged vN . It carries the request (the words people gave the Builder), the diff (file changes), who (the Editor who applied) and the migration id when there is one. Commit message Shape: <first request line> then trailers Request: (one per request, in order) · By: @mona · Version: 12 · Migration: 0012-deal-negotiation · Check: pass (2 rounds) . Versions… App ⌄ → Versions… lists vN · who · when · requests; each opens Show diff (screens rendered side by side with Compare, files as text). Revert to vN creates a new version whose diff undoes the later ones; history is never rewritten. Content versions Each part save is a commit on content/ with trailers Part: · By: (person or “CRM agent” ) · Via: Ask | Nudge | Comment . Versions per part read this log; Restore = a new commit. Records Not in git. records.db keeps record history rows (record, field, before, after, who, when, version). Undo uses them. Git engine go-git (pure Go) inside the codeaf binary. Repos never leave the server; members never clone them. Open files (App ⌄) shows them read-only.
Drafts a scratch overlay over real data
Start Shape creates drafts/<who>-<id>/ : a git worktree of definition/ on branch draft/<who>-<id> and an empty overlay.db . Base version recorded (v12). Reads Every query in the draft reads records.db with overlay.db laid on top (overlay rows win; overlay tombstones hide). Label in the card: “reads real data · saves to a scratch copy” . Writes All record writes go to overlay.db . Runs started in the draft use connector fakes; nothing is sent, no budget is spent except Builder and model tokens. Discard Deletes the draft folder. Nothing else changes. Apply Check passes → migration dry-run shown → Apply: the draft branch merges into definition/ as vN+1, the migration runs on records.db in one transaction, realtime pushes vN+1 to every member [S-A3]. overlay.db is thrown away: writes made while trying the draft were tests on a copy. Lifetime A draft lives until Apply or Discard. Drafts untouched for 30 days show “Old draft · Discard” in Versions…; never removed silently.
Replay two drafts at once
1 Mona's draft is based on v12 . It stores each request with its diff: R1 “add a Negotiation stage” , R2 “show weighted on the panel” . 2 Raj applies his draft first → v13 . Realtime tells Mona's draft “CRM is now v13” . 3 CodeAF makes a new draft branch from v13 and hands the Builder R1, then R2, with v13's files. The Builder re-plans each one (it does not patch the old diff). 4 Check runs on the replayed draft. Pass → banner “Your request was replayed on v13 · Show diff” . Overlay rows are kept. 5 Fail after 3 rounds → “R2 could not be replayed on v13 · Fix it · Drop R2” . R1 stays applied in the draft.
