1 Use · Shape is the switch in every app’s header line (CodeAF-owned). Use works in the app: the pane is the Slides agent and changes content (decks, slides). Shape changes the app itself: the pane becomes the Builder (CodeAF’s own agent), which writes screens/*.json , app.json and runs; the draft bar appears and the plan opens on the left. Flipping back to Use keeps the draft.
2 Draft bar. Each ask in Shape is one change. The bar counts them and quotes the words. Show diff lists changed files; Apply writes the next version; Discard drops every change in the draft; Versions lists applied versions with Restore.
3 The plan as a menu. Same sections as the plan card: Data · Automation · Screens · Agent · Needs. Clicking a screen shows it in the centre (here Screens › Deck). Every line edits in place, as on the plan card. Needs is computed by CodeAF; a change that adds a capability shows in it as new.
4 The running app, as a draft. The centre is the real Deck screen running with the draft applied, on this app’s data (here the sample deck). It is fully clickable; the label reads real decks · saves to a scratch copy means trying it never changes a real deck. Change 1 added the Templates tab; change 2 put the brand fonts on every slide.
5 Builder · shaping the app. The pane is titled with the CodeAF mark, the same Builder in every app, never the Slides agent. Each change runs Check (schema, kit law, render, behaviour on connector fakes) before it lands in the draft; a failed check stays in the pane and never reaches the team.
6 Who sees what. Only Santosh sees the draft. Once Slides is applied, members of acme keep using the applied version while anyone’s draft is open (B5).

Checks CodeAF (shell) Schema check, kit law, render with sample data, behaviour check on connector fakes. Before every preview and every change. Use · Shape · draft bar CodeAF (shell) Show diff · Apply · Discard. One draft per person per app; only its author sees it. Versions · Activity CodeAF (shell) One version per apply, one Activity line with View and Undo. Builder · agent pane · Inbox · approvals CodeAF (shell) The Builder (Shape) is CodeAF’s own agent and changes the app. The Slides agent (Use) is a normal CodeAF agent and changes content only.
