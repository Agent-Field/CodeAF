title: a task's check runs in its own copy, and a piece that comes home late folds into its parent
pr: 911
surface: [chat, engine, docs]
invalidates:
  - "A declared check's absolute path is NOT safe to run as written, and never was. `taskCopy.bind` bound a contract's `work`, `deliverable`, `acceptance` and `expects` to the task's own copy (#566) and left `checks` alone, so `grep -q rewritten /person/folder/report.txt` — what a parent standing in that folder is asked to write — ran with the copy as its working directory and read the person's untouched original. It answered red, the checker hunted for files its own check named, and correct work landed `your call · nobody could check it` (#886). The same address made the before-reading read the person's folder too, so a check this work really had broken came back \"red before this work and remains red\"; and a check whose FIRST word was an absolute path into that folder was dropped from the checker's door without a word. A check is now bound onto the copy it is RUN in, by the same bind, at the one place a check becomes a door (`auditDoorFor`): an address at or under the folder the work is about is read where the check is being run — the clean copy of what would ship, the commit the work was cut from — and an address anywhere else stands as written. `auditDoorFor` takes a `taskCopy` (`Agent.checkCopy` for a task, `standingOn` for a checker standing on the folder itself) instead of a bare directory."
  - "A piece handed out by a task that lands after its parent stopped reading is NOT sent to the person's conversation any more. The parent's seat is withdrawn the instant its worker's reading is over, and the parent stays open through its check and its landing for minutes; a piece landing in that window used to fall past the family to the person, and its result never reached the deliverable it was cut from. It is now folded into the parent's own report (`landingFold`, `task_latefold.go`) as the piece's own landing line, report and changed files — the RECORD the sender composes beside its note (`delivery.record`, `landingRecord`), never the note itself, which opens by telling a model which word to say back — and reaches the person inside that parent's landing. The fold is the delivery's acknowledgement, so the checkpoint marks the piece announced and a restart does not tell it again; the report's two halves (`late`, `landed`) are on the checkpoint, so a fold after a restore adds its piece and nothing else. Only a piece whose parent has already landed is announced on its own. The fold is not a turn and the parent's check does not see it — the checker reads the worker's own last words, written before the piece came home, and is not asked twice."
---

The two halves are one belief corrected: a task's copy is the world its whole
life happens in, not a detail of where its worker stands. The check half is
spelled as the directory a command is run in (`.`) because a task's check is
run in several copies of one ground and only that spelling is true in all of
them; binding to one named directory would have fixed the checker and broken
the before-reading. `docs/design/task-start/DESIGN.md` carries both halves.
