title: codeaf app sends pictures and what was marked on them as one message
pr: 0
surface: [engine]
invalidates:
  - "Was true: a picture attached in the app reached the model only as the words `Attached file: <path>`, and `SubmitImage` (real image parts) and `SubmitMessage` (the person's words and attachments kept on the line) were separate doors, so no message could be both a picture and a mark. Is true now: `agents.send` takes an optional `submission` naming which staged attachments go as pictures and a structured annotation (pins, boxes, shaded areas in 0–100 picture coordinates, ordered notes, change-only-marked); the engine reads the staged file once, sniffs its type, and sends it as an `image_url` part in the same single user message that carries the words, the attachment chips and the annotation."
  - "Was true: a message had no identity beyond its place in the transcript. Is true now: a message sent with `submission` is given a `msg_` id when the engine accepts it, recorded on its journal line and returned in the `agents.send` answer, on the live user entry and on the entry after the conversation is reopened."
  - "Was true: a blind talk model given a picture answered from the vision model with nothing recorded about who looked. Is true now: the message records `delivery` as `description` and the vision model that looked (`seen_by`), or `image` when the talking model received the pictures."
  - "Was true: every picture sent or replayed sat in the live transcript as its whole base64 string for the rest of the session and was re-sent on every request, so opening a conversation with 200 pictures read and encoded every file. Is true now: the transcript holds a small immutable reference (path, digest, type, size) per picture and a replay opens no file; the bytes are read, checked against the recorded digest and encoded only by the request that carries them, for the newest pictures within 40MB decoded and 64 pictures per request. A picture is charged against that budget before its file is touched and keeps the charge when the file turns out gone or changed, so a history of missing pictures costs at most 64 attempts. Older pictures appear in that request alone as the placeholder sentence naming their path, and the conversation still holds every reference. A picture whose file moved or changed since it was accepted is that placeholder, not a different picture."
  - "Unchanged and still true: a conversation hosted on an engine that has not said it takes pictures (`composedMessages` in its welcome, `messages.media` in hello) refuses the whole message with unknown_method rather than sending its words alone; a refusal of any kind leaves every staged attachment staged."
