title: a specialist's task page carries its stages, actions and ending on the app wire

surface: [engine]
invalidates:
  - "Was true: `appwire.TaskPage` was `{task, result, files, log, notes, brief}` and a specialist's stages, shown actions, ceiling, models, listening state and ending facts reached only the terminal (`session.PlanProgram`); `session.AppTask` read the page and threw the program away. Is true now: `TaskPage.program` (`appwire.TaskProgram`) is present for a task a specialist was handed (`session.AppTaskView.Program` carries it over `--host`). Stages are the hello's own list with the person's word for each (a wordless stage keeps the word before it); senior-dev's 15 stages are 7 consecutive words, not 6, so the app groups consecutive equal words and nothing is forced to six. NOT carried: attempt number, `auto` or earlier runs (the record is the latest process, not a history), a stage index or percent, a step's `detail`, and any file handle for `reports` (display names only). Absent `program` is also what an engine that predates the field sends."
  - "Was true: a program's lines were tied to its current process by time (`at` at or after the record's `started_at`), so a clock that stepped back, a start equal to the old ending's time, an old line written late, or a relaunch before its hello put the previous run's ending, stage and actions on the new run. Is true now: every launch has one identity its producer draws before the process exists — the descendant-sweep marker `delegate.Run` already drew, now caller-supplied (`delegate.NewLaunch`, `Launch.Marker`) — stamped as `launch` on `delegate-program.json`, on a new `start` line written to `delegate-actions.jsonl` before the process is spawned, on every action line and on every turn in `delegate-conversation.jsonl`. No program's vocabulary shows the `start` line. The app's actions, `last_stage`, `ending` and `calls` are the lines carrying the record's launch and nothing else; a record with no launch (older runs, a relaunch before its hello) reads `read: \"unknown\"` with no actions."
  - "Was true: the app's task read read a program's whole action and conversation logs (a 64 MiB history cost 258 MiB of allocation), showed the newest 60 actions with an unreachable `earlier_actions`, counted `calls` over every launch (a rerun's call 1 overwrote the last run's), and an unreadable or damaged log read as `actions: []` or no calls. Is true now: the app reads only the record's launch, looking back from the log's end for its start line and forward over that alone, within a fixed budget (16 MiB, 200 000 lines, 3 s; calls: 32 MiB). `read` is `complete`, `partial` (with `read_cut`: budget, damaged, unreadable, deadline — and then no `earlier_actions`, `before`, `last_stage` or `ending`, and actions only past a damaged line, never from a read stopped early) or `unknown`. `calls` is present only when every one of the launch's turns was read; `0` is a real zero. Every action in a complete read is reachable: `before` is a cursor for the new optional `tasks.program_actions` (`App.ProgramActions` over `--host`); a cursor from a launch the task has since moved past answers `conflict`. A launch beyond the byte/line budget remains explicitly partial without a cursor; lifting that limit requires serialisable canonical-reader checkpoints. The terminal's `PlanTaskPage` still reads whole logs as before."
  - "Was true: `appwire.EndingFacts` had no `nothing_to_audit`, so sec's true-only fact was dropped on the wire; `models` crossed without the secret filter; an unknown `hunt_coverage` crossed with whatever counts sat beside it. Is true now: every `delegate.EndFacts` field crosses under its own key (a reflection test fails on a field without its wire twin), `models` are redacted like every other text, and an unknown coverage account is `{unknown:true}` alone."
  - "Was true: the new launch reader opened action and conversation paths as ordinary streams, so a special file could block or look like an empty launch; the app still read unbounded program metadata. Is true now: the shared regular-file opener refuses pipes/devices and checks the opened descriptor, and program metadata is limited to 5 MiB (a whole hello line plus its fields) for EVERY reader of `delegate-program.json` (`delegate.ReadProgram` is the bounded read: the task read, the plan rows, the run clocks, recovery and the index), so a FIFO where the record goes no longer holds `tasks.get` or `tasks.program_actions`, and a page of older actions no longer builds the whole plan page. Unsafe or over-budget input is unavailable, never an invented zero."
