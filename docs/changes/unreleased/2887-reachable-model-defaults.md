---
kind: fixed
title: Default models come from a connected provider when OpenRouter is not connected
pr: 2887
surface: [engine, app, chat]
invalidates:
  - "The built-in defaults (the conversation model, the free chat default and the fallback models row) were OpenRouter ids used whatever was connected, so a ChatGPT-only profile failed every message with no API key and an Ollama-only profile still sent its fallback to OpenRouter. With an OpenRouter key every built-in stays exactly as it was. Without one, each built-in default is kept only while a connected service can send it; otherwise every slot follows the conversation model's provider: its preferred or strongest model for the conversation, and a different strong model for the fallback (the conversation model itself when the providers offer only one). A hosted provider is preferred to a local server for the conversation, and the fallback stays on the conversation model's provider. The reflex, small work and knowledge rows follow the conversation model (#2890), so they reach it too. A terminal chat re-reads its default fallback when it moves onto a provider connected after launch. With nothing connected, or when no connected provider can say which models it offers, the built-in ids stay named as before."
  - "The fallback models row in settings named DeepSeek V4.1 Flash as its blank default; it now says codeaf's default, which is that model with OpenRouter connected and a model the connected providers offer otherwise. The legacy nearest-in-the-catalog fallback in an old saved conversation migrates to codeaf's default fallback for the profile (the OpenRouter id with OpenRouter connected) rather than always to the OpenRouter id. The row is marked changed in the terminal's settings only when the profile holds a value of its own."
  - "The desktop's models.list offered the engine's default as an extra row even when no connected service could send it; it is now offered only when one can, so first-run setup cannot save the built-in OpenRouter model while a connected provider's list is still arriving."
  - "A built-in default that routes to a connected provider by its prefix (for example deepseek/deepseek-v4.1-flash with a direct DeepSeek account) is kept only when that provider lists it; a provider that publishes no list offers its preferred model and the model its connection check uses, so the fallback has a second model there too."
  - "ChatGPT's crew routes served only the vendored preferred model (gpt-5.5), which a ChatGPT account may not list; without an OpenRouter key they now serve the account's remembered models, and the preferred id only while nothing is remembered. With OpenRouter connected they serve the preferred id alone, as before."
  - "ChatGPT's remembered account models now keep their thinking levels, used only to rank them; the rows still do not claim a published reasoning profile."
