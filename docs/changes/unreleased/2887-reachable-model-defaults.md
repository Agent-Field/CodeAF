---
kind: fixed
title: Default models come from a connected provider when OpenRouter is not connected
pr: 2887
surface: [engine, app, chat]
invalidates:
  - "The built-in defaults (the conversation model, the fallback models row, the reflex and small work helper tiers, the free helper and chat defaults, and the knowledge model) were OpenRouter ids used whatever was connected, so a ChatGPT-only profile failed every message with no API key and an Ollama-only profile still sent its fallback, titles and routing to OpenRouter. With an OpenRouter key every built-in stays exactly as it was. Without one, each built-in default is kept only while a connected service can send it; otherwise every slot follows the conversation model's provider: its preferred or strongest model for the conversation, a different strong model for the fallback (the conversation model itself when the providers offer only one), and its lightest model for the helper tiers and knowledge. A hosted provider is preferred to a local server for the conversation, and the fallback and helpers stay on the conversation model's provider. A terminal chat re-reads its default fallback when it moves onto a provider connected after launch. With nothing connected, or when no connected provider can say which models it offers, the built-in ids stay named as before."
  - "The fallback models and knowledge rows in settings named DeepSeek V4.1 Flash and an OpenRouter model as their blank default; they now say codeaf's default, which is that model with OpenRouter connected and a model the connected providers offer otherwise. The legacy nearest-in-the-catalog fallback in an old saved conversation migrates to the profile's default fallback rather than always to the OpenRouter id."
  - "A built-in default that routes to a connected provider by its prefix (for example deepseek/deepseek-v4.1-flash with a direct DeepSeek account) is kept only when that provider lists it; a provider that publishes no list offers its preferred model and the model its connection check uses, so the helper seats can take a light model there too."
  - "ChatGPT's crew routes served only the vendored preferred model (gpt-5.5), which a ChatGPT account may not list; they now serve the account's remembered models, and the preferred id only while nothing is remembered. This applies with OpenRouter connected too: a crew seat on a ChatGPT plan may take any model the account lists."
  - "ChatGPT's remembered account models now keep their thinking levels, used only to rank them; the rows still do not claim a published reasoning profile."
