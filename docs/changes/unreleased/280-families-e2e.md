Everything this lane asserts is on disk — the person's own directory, the family
tree's git history, the session's task records, and the division records in the
workers' own journals. Not one assertion reads the model's prose, because a model
saying it divided the work is exactly the claim the file exists to check.

The three scenarios are a three-section report on a plain folder (the mirror is a
repository, its parts cut worktrees off it and merge back, and the family's whole
ledger reaches the folder, which never gains a `.git`), a two-part write-up on a
repository (the same laws where git was always underneath, and one landing onto
the person's branch), and a division whose two parts both claim `report.md`
(refused at admission, nothing admitted, the path named, the worker carrying on).

The WIP-checkpoint reading is written and waiting rather than deferred: it asks
git whether the tree a part's work arrived on holds the parent's plan file, which
is the issue's own question asked of a commit instead of a worker. Where the
family history holds a `wip:` checkpoint the answer is required; where it does
not, the absence prints as a pending finding rather than as this lane's red — so
the assertion turns hard by itself the moment that commit starts being written.

Every model row is pinned at one cheap model and the pin is CHECKED rather than
assumed: each scenario reads the machine's own usage ledger back and fails if a
second model answered. That also makes the cost line honest — the ledger carries
every call at every depth, auxiliary ones included, with no folded lines to
double-count. A whole run is about four minutes and six cents.
