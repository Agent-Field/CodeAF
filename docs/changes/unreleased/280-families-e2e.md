Everything this lane asserts is on disk — the person's own directory, the family
tree's git history, the session's task records, and the division records in the
workers' own journals. Not one assertion reads the model's prose, because a model
saying it divided the work is exactly the claim the file exists to check.

The four scenarios are a three-section report on a plain folder (the mirror is a
repository, its parts cut worktrees off it and merge back, and the family's whole
ledger reaches the folder, which never gains a `.git`), a two-part write-up on a
repository (the same laws where git was always underneath, and one landing onto
the person's branch), a division whose two parts both claim `report.md` (refused
at admission, nothing admitted, the path named, the worker carrying on), and an
edit the person saves in their own folder while the work runs (the landing stands
back, names the file, and leaves both versions on disk).

The checkpoint reading asks git whether the tree a part's work arrived on holds
the parent's plan file — the issue's own question put to a commit instead of to a
worker, with a token minted for the run so nothing about the answer can be
guessed. Both halves are required, because a checkpoint that carried nothing
would pass on the commit alone and a part that wrote the plan itself would pass
on the file alone.

What a commit's subject SAYS is a finding rather than a law. A worker is told
never to commit; one that ran `git commit` inside its own worktree has still
worked in isolation and still merged back, so the lane says so out loud and holds
its reds for the claims the wave actually makes.

Every model row is pinned at one cheap model and the pin is CHECKED rather than
assumed: each scenario reads the machine's own usage ledger back and fails if a
second model answered. That also makes the cost line honest — the ledger carries
every call at every depth, auxiliary ones included, with no folded lines to
double-count. A whole run is about four minutes and six cents.
