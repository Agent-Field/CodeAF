title: A task that only reads its folder says so when it starts, to its worker, and when it lands
pr: 2909
surface: [engine, chat]
invalidates:
  - "A task whose stand is a reference (TaskModeReference, a ground it only reads) was told so on its receipt only when `where` named a folder holding the home folder (homeTaskRedirect). Where the proposal's `ground` or its brief had chosen the folder, the receipt read \"It works in <ground>, the folder this proposal gave as its ground.\" or \"It works in <ground>, the one folder its brief names the work in.\", the home folder included; on the other rungs it had no sentence about the folder. On every rung the receipt of a task the conversation's model proposes now reads \"It reads <ground> and writes only in a folder of its own, so nothing in <ground> changes: this proposal named no file there by full path. If the work is meant to change <ground>, stop this task and propose it again naming the files it makes or changes by their full path under <ground>.\" (taskReadsSentence), or over the home folder \"The task reads <ground> and keeps what it makes in its own folder; nothing in <ground> changes.\" whichever door named the folder. A task a person types with `/task` is handed no receipt sentence about its folder on the run road, and on the older single-task road only the stand's redirect, as before."
  - "A reference worker was told \"<ground> is yours to read, not to change. Everything you make goes in <dir>, your own folder. In your report, say where in that folder the results are.\" only when its ground held the home folder (taskCopy.readsHome, withHomeReadingNote); over any other ground it was told nothing. Every reference worker whose folder is not its ground is now told \"<ground> is yours to read, not to change. Everything you make goes in <dir>, your own folder, and stays there: nothing you make reaches <ground>. In your report, say where in that folder the results are, and never say the work is in <ground>.\" (taskReadsNote; the field is taskCopy.reads, and the run's helper is withTaskReadsNote)."
  - "A run that only read its ground was handed to the engine's landing, which failed in its folder with \"fatal: not a git repository\": a plan note \"the run's landing failed\" was filed, the landing had no line (RunLanding.Line empty, no branch) and the run's page got no homecoming note. Such a run is no longer handed to the engine's landing (landReferenceRun): its landing line reads \"it changed nothing in <ground>: what it made is in <its folder>\" (referenceLandingLine), and its page carries that line once, in the run's outcome note, with no separate homecoming note. A reference run that failed is given the same line; one that was stopped is given none."
  - "A reference whose proposal asked for `where: \"in place\"` inside a repository had the redirect \"in place was asked for, and <ground> is a repository — the work goes on a branch cut from it instead\" printed on its receipt. The stand still carries that redirect, and the receipt of a reference no longer prints it (taskStandRedirect)."
  - "A hand-off that joined a live run was told about its own stand: a reference that joined a run working in a copy of the same ground got the read-only receipt and its worker the read-only note. The receipt sentence and the worker's note of a joined hand-off are now decided by the mode of the run it joined (startOrJoinTaskRunVia answers that mode). A hand-off that joined a run which only reads its ground, the home folder apart, is not given the starting task's sentence or \"It joined the work already underway and shares its copy.\": its receipt reads \"It joined the work already underway, which only reads <ground> and writes in a folder of its own, so nothing in <ground> changes while it is part of that run. To change <ground>, propose the work once that run has ended.\" (taskJoinedReadsSentence), whatever files its own proposal named."
  - "Over the home folder, the read-only note of a run was appended to the run's brief before its crew was routed (withHomeReadingNote in startOrJoinTaskRunVia), so the brief a crew kept (taskCrew.brief, TaskCrewRecord.Brief) and the text it was routed on carried the note. Over every ground a run only reads, the note is now added only to what the workers are given: the store's root description, RunSpec.Brief, and the brief a deferred run keeps (beltRun.brief, PendingRunRecord.Brief). The crew's kept brief, which `/redo stronger` and a rerun with routing read again as a contract, is the brief as it was handed in."
  - "The manager's first law ended \"Asked what is happening, answer from the team.\" It now adds \"A task (propose_task) is not a member: use one only for work no member is here for, or when the person asks for a task, and never to get round a member that did not start. When a member did not start, team_send's answer says why: tell the person that.\" The law's earlier sentences are as they were."
---

A proposal that named a repository as its ground and no file by path was read as
work that only reads it. The worker built the project in its own folder, reported
it integrated, and the conversation told the person to run it from a repository
nothing had been written to.
