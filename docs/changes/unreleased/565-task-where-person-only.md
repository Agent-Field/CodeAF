title: a task's where is not a decision; isolation is judged from their words
pr: 565
surface: [engine, chat]
invalidates:
  - "A non-empty `where` on a task — `in place`, `.`, `here`, or the conversation workspace path — used to skip the ground ladder and stand the worker in that directory. The field is ignored. Ground is which folder; mode is how it stands."
  - "A path the person named used to mean in-place in that folder. It is the ground — the project the work is about — and the task still gets a copy of it."
  - "The `/task` shaper was told to set `where: in place` for work it judged 'not code work'. That line is gone. Isolation is not the shaper's job."
  - "Opting out of a worktree is not a phrase match on `in place`. A cheap judge reads the person's request and answers one bit; every failure is a no, and the task still gets a copy of its own."
---

The proposing model and the shaper both fill `where`. Neither is the person
opting out. The copy is the default; un-isolation is their words, or a place
they already marked, or a folder with no repository to cut from.
