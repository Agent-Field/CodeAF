title: a picture a shell command makes can be published as a source of the answer
pr: 0
surface: [engine, chat, app]
invalidates:
  - "A file created by `bash` was never recorded: no seam observed it, so a Python chart reached the person only if the model wrote its path into markdown, and a later `view_image` of it was evidence, not anything made. `bash` now takes an optional `outputs` array (at most 8 paths). The engine looks at each path (lstat, never opens it) just before the command and again after it ended with exit status 0 in that call, hashes it through one descriptor under the image limit, one total read budget and one deadline, and records a media source of origin `published` tied to the call's run and tool ids (`message` only where the producer supplied it). Nothing is read from the command, its output or a file name."
  - "`created` means exactly absent before, a regular file after, with no other job or overlapping tool call of the session; an existing file is `unchanged` or `modified` and never a Created deliverable; only `created` also carries a deliverable fact. Presence does not prove a paid generation: charge stays unknown. Background, promoted, failed, timed-out and interrupted commands register nothing, a file that changes while it is read is not registered, and a record that cannot be written is reported as unknown, not complete."
  - "The wire `origin` enum of a media source gains `published`, with optional `declared` and `change`. Evidence stays evidence. Audio, video and documents are not published this way."
---

`bare` gains `WithBashExit`, a structured report that the shell process ended on
the ordinary path with a known status, so no result text is read to learn it.
The model is told in `bash`'s description to list the path of a picture it makes
for the answer. Design and audit: `SHELL-OUTPUTS-CONTRACT.md` in the panel
deliverables log.
