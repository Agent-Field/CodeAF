  - "The delivery gate's subject was decided from a list that a workspace walk wrote into. `Evidence.completeAgainstTheWorld` settles every name the request or the plan spelled against the disk, and it APPENDED what it found to `Evidence.Artifacts` — the same list that answers what the run CHANGED. So a run whose contract opened `Read CLAUDE.md at the repository root before you start`, and which made 156 shell calls and not one write, reached `Subject()` with one entry, was judged under the tree contract, and was handed a block opening `This deliverable is the CHANGE THIS RUN MADE TO THE TREE — 1 file` with that file printed entire. The judge named the only file of the record, exactly as that contract requires, and refused with `CLAUDE.md — The only file this run changed is CLAUDE.md` over a run whose own closing account says it produced nothing (2026-09-03T08:24:30Z, the `aforge do` hand-off of #510). The store kept `subject = \"tree (1 file)\"` for it, so the invention was in the journal before any model saw it. NOW: the walk's answer lands in `Evidence.Swept`, and existence decides nothing about change — the subject, the tree the fence holds, the record a refusal may name, the changed-code reading, the mechanical rule check and the acceptance focus all read `Artifacts` alone. A run that changed nothing is judged as the claim it is, and the refusal's words are about the worker's message."
  - "The walk's own question keeps its answer, and it is now the only question the walk answers. The mechanical promised-file gate, `Evidence.MissingPromised`, `AdmitGapArtifact` and the promised-file half of a judge's own verdict read `Artifacts` and `Swept` together, so the request that named `feature_schema.joblib` and found it at `model_results/feature_schema.joblib` is still answered by the filesystem rather than by the registry. `AdmitGapPresent` and the record block are NOT in that set: a file the run merely read is not a world for a finding to be checked against."
  - "The block that settles the request's named files said `produced, at <path>` for a file the run had written and for one that was simply already there. It now says the second in words of its own — `a file of that name is there, at <path>; this run did not write it` — so the record a judge reads cannot report a file the run never touched as something it produced."
---

A refusal names only what the photograph shows. The correct half of that refusal
was reached over an invented half, and the invention was one line: a walk whose
job is to answer *does the workspace hold a file of this name* wrote its answer
into the list that answers *what did this run change*. Those are two questions,
and for as long as one list held both, a file a request told a worker to READ
was indistinguishable from a file the worker wrote.
