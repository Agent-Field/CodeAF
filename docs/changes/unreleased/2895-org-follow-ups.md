kind: changed
title: private chats stay private, a team server stops trusting its own computer, and people can make bots
pr: 2895
surface: [factory, app, engine, docs]
invalidates:
  - "Was true: everyone who could see a workstream was listed every other person's chat in it, with its title, owner, state and last-activity time (the v2 ruling C10), whatever the chat's own privacy. Is true now: chats start private (the organization policy's default for chats, unchanged), and the list shows another person's chat only when it is shared with you; a private chat is hidden from the workstream's people and from the operator, and the server does not announce it when it is made."
  - "Was true: sharing a private chat with one person opened it to the whole workstream and to the operator, because the chat then inherited the workstream's shares and grants. Is true now: a private chat that has been shared stays private and is reached by its owner and the people its own grants name, and by nobody else, the operator included unless the policy says it sees private things; the grants list and the audience of its events name the same people."
  - "Was true: #2890 removed the chunk-paged remote chat read, and dev's chats.read hello word and its agents.entries behaviour were the only chats.read. Is true now: the paged read is back as the method chats.read {cell, before?, limit?}, answered newest page first with sealed_at_ms and fetched_bytes, under its own hello word chats.read.paged. Dev's chats.read hello word keeps its meaning (agents.entries follows a saved remote head) and is not what advertises the paged read. The furrow pin is v0.3.7."
  - "Was true: a request from the server's own computer with no sign-in acted as the factory's owner on every factory, team servers included, so any program on that machine was the owner. Is true now: that holds only on a solo factory by default. A team factory refuses a credential-free request from its own computer like any other, unless the host config says loopback_trust: true. A forwarded request is never local whatever the key says, unless a listed proxy names a loopback client in X-Forwarded-For; a script on the server's machine that called a team factory without a token must now send one (the discovery file carries it) or set the key. Registering a runner follows the same setting: a team factory with it off asks a runner on its own computer for a runner credential (the host's access token or a signed-in person's session) like a remote one, and the factory's own person no longer stands in for a runner that names no handle; solo is unchanged."
  - "Was true: the only identity that could call an organization server was a person, signed in or holding a person token. Is true now: a person can make a bot, a named identity with its own token (cbt_, shown once, stored only as a hash), that acts with at most its creator's rights at the moment of each request. It is default-deny with a route allowlist, cannot start an agent run, make bots or use operator routes, and ends with its token, its removal or its creator's removal from the organization."
---

The two defaults that move on purpose are chats (private) and loopback on a team server (off); both have a way back and both are in the manual. The paged read and the bots are additive. The desk has to gate on `chats.read.paged` before it calls the paged read, and the manual's sharing and factory pages carry the rest.
