  - "A 404 was classified by three unrelated rules — internal/taxonomy's `classOf`, internal/provider's `refusalKind`, internal/session's `providerCouldNotServe` — each correct about the half it had been told and each growing a special case every wave. There is now one: the transport decides STRUCTURAL FACTS once at its refusal door and carries them typed (`APIError.Routing`, `.Account`, `.Withdrawn`, `.Overflow`, `.Code`), `provider.Evidence(err)` is the one extractor and makes no decision, and `taxonomy.Classify` is the only function in the tree that turns evidence into a class and an action. A law test (`internal/taxonomy/classifier_law_test.go`) fails the build on a `.Status` compared against 400 or above outside internal/taxonomy and internal/provider."
  - "internal/session's turn loop ran `isContextOverflow(errMsg) || !isRetryable(errMsg)` over the provider's prose and RETURNED on it, forty lines after the verdict had read the same failure off typed evidence — a string deciding what a typed classification had already answered. `isContextOverflow` and its seven-branch regex are deleted; `isRetryable` remains as EVIDENCE for `taxonomy.Evidence.Wire` and decides nothing. A context overflow is structural now: the request-too-large status and the error envelope's own `code`, with the sentence kept only as a last-resort hint inside the transport."
  - "`taxonomy` had three classes. It has four: `Shape` is the REQUEST — a transcript longer than the window, or bytes the router itself read and refused — and its moves are real, `ActionCompact` (once per turn) and `ActionReshape`. A 4xx that named no upstream used to be `Work`, the same word a job that could not be done gets, so a turn ended blaming somebody's request for their conversation."
  - "A spent relaxation ladder (`provider.RefusalError`) was read as `taxonomy.Work` and ended the turn with the router's own sentence on screen while a chain the person had configured sat unasked. It is `Evidence.Spent` now: `Transport` with its budget declared gone, whose one move is the caller's chain. `provider.RoutingRefusal` still answers false for one — there is no machine and no shape left THERE — and that is a different question from \"was anything learned\"."
  - "`Verdict` named two exported types in packages that call each other: internal/taxonomy's control answer and internal/provider's learning record. The learning record is `provider.Reading` (file `reading.go`, constants `Reading*`), internal/lane's watch answer is `lane.Advice`, and `TestOnlyOneVerdictTypeExists` holds the module to one. Struct FIELDS named `Verdict` that carry a `provider.Reading` keep their names and their JSON tags, because those are on disk in profile records and plan graphs."
  - "The refusal door asked `canWalk()` — a PREDICTION that the walk would carry a refusal — and then `deferLadder(body)` to record that it had relied on one; #835 added `exhausted()` to catch the misses, so the prediction and its repair both existed. There is one call now, `takeRefusal(body)`, which asks and records in the same critical section, so the answer and the promise cannot disagree. `exhausted()` is the fulfilment of that promise rather than a repair. `canWalk` survives only as `walkAvailable`, a reading with one caller (retry.go's `retryElsewhere`) that is not a handoff."
  - "TWO mechanisms changed a request's model from one `FallbackModels` list: `endpoints.go`'s `fallbackChain` walk at the foot of the relaxation ladder, `recoverFromPacing`, and internal/session's turn loop — none of them knowing the others had already tried a model. Both adapter walks are deleted; the relaxation rungs stay, the adapter never changes the model, and `session`'s `ActionHop` is the only model change in the build. Live evidence from 2026-09-10 22:32 says why coordinating them was not enough: the adapter's hop carried the ORIGINAL model's `provider.only` across to the new model and was answered `404 No allowed providers are available for the selected model`, because a lane pin is per model and nothing re-derived it. The person-facing `Retry 1/1: Falling back to <model>` line is gone with it; the turn's own `moving to <model>` line is what a person reads."
  - "`nextFallback` picked the next model by indexing the chain with a count it kept itself — `options[len(hopped)]` — which is only right while nothing else hops. It reads `provider.ModelsTried(ctx)`, a per-turn record every send writes at the one door it passes through, and answers with the first model on the chain that is on neither list."
  - "A model the router carries with ZERO endpoints was indistinguishable from an emptied endpoint set: the same 404, the same sentence, and it spent the whole transport budget buying three more identical refusals before the hop that was the only move all along (measured 2026-09-10 22:39 — three sends thirty milliseconds apart, every turn, and the next turn hopped somewhere else because nothing remembered). It is `Evidence.Withdrawn` now, decided structurally (`Client.withdrawnModel`), hops at once with no budget spent, and is remembered for the life of the process: a later request is not sent at all and the chain does not offer the model. An answer clears the memory; nothing is written to disk."
  - "The empty-200 re-ask took the boundary's verdict, took the wait, and told the surface NOTHING — no `EventRetrying`, no `RetryNews`, no phase — so a person watched a clock counting a request that had already come back empty. It now emits one `EventRetrying` (`nothing came back from the model — asking again`) with its `RetryNews`, and narrates a non-zero wait on the same phase pipe the ladder uses."
  - "A turn that ended on a provider failure handed out the router's own sentence — `API error (404): 0 endpoints out of 1 requested are available matching your guardrail restrictions and data policy`. It never does: `endingWords` puts the boundary's person-facing sentence in front, with the typed failure reachable underneath so every layer that decides by type still can. The new sentences are `that model is not being served any more`, `your key was not accepted for this model`, `this conversation got too long for the model`, `this conversation is too long for the model even after shortening it` and `the request could not be sent as it was`, and `internal/manual/chat/models-and-cost.md` has the table."
  - "`provider.RefusalError.Tried` named the fallback models the adapter had walked. The adapter walks none, so the field is deleted and its advice branch with it; the layer that hops says what it tried, in its own words, because it is the layer that knows."

This is `docs/design/recovery/DESIGN.md` §7 row R2, and the defect it closes is not
a wrong line anywhere. Four waves in two weeks each added a correct special case to
a DIFFERENT rule about what a failed call meant, and #835 had to add
`Evidence.Routing` to work around one of them. The shape that allows that is what
this removes: the transport states facts, one function turns facts into a move, and
three go/ast laws fail the build on the next site that tries to answer for itself.
