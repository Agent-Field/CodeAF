invalidates:
  - "An answer to `ask` was the return value of the call that asked, and existed for the model only while that call was parked. It is now delivered: to the call parked on it where there is one, and otherwise onto the conversation's own queue through `Agent.accept` — the same road a background job's ending takes, landing at the next step boundary or waking an idle conversation. What the model reads is one rendering either way: a sentence saying what happened (`answered · question 3 · …`) and the whole `Answer` under it. A model or a test that expected bare JSON from `ask` reads a sentence first now."
  - "`ask` always stopped the turn. It still does by default, and `blocking: {turn: false}` now returns at once with the question standing; the answer arrives later as a message opening `answered`. An absent `blocking` still waits, so nothing a model wrote before this behaves differently."
  - "The book of parked asks (`askedOfThePerson`, `internal/session/askwait.go`, #870) and the lane's own account of a question were two maps holding one question. They are ONE — `Agent.asks` of `*modelAsk`, in `internal/session/asklane.go` — and that file carries #870's three endings word for word plus the fourth this adds: a call that never waited. `THE ENTRY IS THE OWNERSHIP` is now `THE CLAIM IS THE OWNERSHIP`, because a settled entry is kept so its answer can be changed."
  - "The recommend-then-auto clock lived inside `executeAsk`'s select, so a question nobody was parked on had no clock at all. It belongs to the lane now and runs regardless; the length is one derivation (`autonomyClock`) — the person's own `/autonomy` figure, or `awayAfter` where they named none — and `/autonomy <kind> recommend` no longer requires a duration. A clock decides nothing once the session has closed, and an answer a closed conversation cannot read is refused instead of recorded."
  - "A key on a question stopped only the SURFACE's reading clock; the engine's clock went on and could take the pick under somebody's hand. `Agent.HoldQuestion(kind, token)` (wire `Question.Hold`) stops it for good, clears `Question.Deadline` and says the question again, the row reads `paused`, and while the clock runs the question carries a dim line saying `any key stops the clock · you can still change the answer afterwards`."
  - "`c change` on a receipt named a key nothing handled. It asks the same question again while the receipt is on screen and the box is empty; the answer carries `Answer.Revises`, the new record says `changed from <what it replaced>`, and the model is told what changed. `u undo` is beside it on a permission answered `always` and hands that grant back whole — the session memo, the saved settings line, and a connected account's capability, which returns to asking. What may be changed is one reading, `Question.Revisable`, asked by the receipt that offers the key and by the door that takes it; an irreversible decision refuses it in words."
  - "A standing yes to a connected service's tool was written as an account capability INSTEAD of the session memo, and a revision that deleted the memo therefore said `taken back` while the account went on being allowed. What a yes buys is recorded where it is bought (`Agent.rememberGrant`) and `Agent.undoGrant` is the one door that takes back all of it."
  - "An answer to a question this engine is not holding — a row left by an interrupted turn, by a question the person talked past, or by a session host that has restarted — was applied to nothing in silence. It is refused in words now. A second answer to a question already settled is still silent to the person, and it now writes no decision record either: the first answer wins, and the record can no longer disagree with what the model was told."
  - "A `ratify` — `something reversible was DONE … nothing waits on the answer, which is what makes it the cheapest question on the ladder` — parked the turn like every other ask, because an answer with nobody parked went nowhere. It returns at once now and the row waits on nobody; an asker that really wants to wait writes `blocking: {turn: true}`. Every other kind still waits by default."
  - "A question the model asked was `waiting on you` on the presence file and the home page whether or not anything waited on it. The presence predicate reads `Blocking` now, so a conversation working around a question it asked without waiting says it is working. The `QuestionCap` still counts every open question against one subject: a row on a screen costs attention whether or not a turn is parked behind it."
  - "The wire is version 15. A version-14 engine drops `Answer.Revises` as a late answer and answers `Question.Hold` with no such method while its clock runs on, and both fail as silence."
---

Three things the owner picked — carrying on while a question stands, a countdown that
goes with the pick, and changing an answer afterwards — are one mechanism: an answer is a
message that also releases a waiting call when there is one. `internal/session/asklane.go`
holds the lane's book and the one rendering every answer is read in, so a model that asked
without waiting reads exactly what a model that waited reads. A pick the clock takes says
in so many words that it is provisional and can still be changed.
