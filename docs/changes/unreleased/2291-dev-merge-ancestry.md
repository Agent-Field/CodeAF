The merge records dev ancestry and retains non-conflicting app/v3 work. Under
the owner rule, dev wins behavioral conflicts outside Factory. Factory, billing
and ledger dependencies keep app/v3 behavior, including SQLite team storage,
lazy Factory briefs and complete first-sharing backups.

Team sharing is on by default for paired computers. Missing or empty
`teams.share` reads on; explicit off stays off, and damaged configuration or
invalid values read off. The live pairing gate still prevents unpaired sharing.
Solo computers with submitted chats refuse ordinary pairing and explain
`--replace`; replacement retains confirmation and preserved-team receipts.
Unsupported-effort repair is local to opted-in task and Factory clients. Job-owned personal manager turns, reopened completed stages and earlier rounds,
stage conversations, their helpers, manager turns, scouts and triage retain recovery,
including after model or account switches. Live manager turns, brief writing and
Factory page errands (including Step AI and My pipeline AI) opt in per call; the same agent retains ordinary refusal
for its other turns and errands. Ordinary clients return the refusal without a
repair. Pairing acceptance tests use legal startup homes instead of assuming
submitted chats can merge without replacement. Both terminal pairing doors use
dev's completion sentence, asking the person to run codeaf to open their chats.

These choices supersede the earlier merge's opt-in sharing default, keep-and-share
pairing policy and process-wide reasoning repair. Later app/v3 work remains merged.

Chat ownership follows dev too: reopening acquires a new fence, an expired hold
cannot admit tools or desktop sends, and stale move confirmation refuses a
changed fence even when holder and saved head match. Typed desktop refusals and
saved-head metadata remain available.

Explicit replacement clears live chats and shared preferences even when rejoining
the same account. Durable cleanup progress and the destination device distinguish
an unfinished reset from an installed replacement, preserving later writes.

Ordinary file-memo readers retain their missing-file fallback. Profile writes,
daily spending authority, preference/key sharing and live tool-policy reads use
strict reads: unreadable existing configuration cannot be overwritten or treated
as an absent budget or policy. Missing profiles still use their normal defaults.

A failed chat installation leaves the source read-only until a fresh Continue
here action. A released takeover updates the source window to available instead
of retaining a stale continuation notice; release never restores its old fence.
