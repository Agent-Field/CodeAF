Continuing a chat on another computer now splits the critical path from background work across all continuation doors (`Take`, `TakeSeen`, `OpenAvailable`/`takeFree`, Home's `alt+c` resume band, and the app's `agents.open`):

- `StageChat` fetches only the head frame (which embeds the small `.cell/` open-state objects needed to open and continue) in one request, stages `.cell/` directly without cloning the existing workspace tree on warm receivers (`open_seed=`), checks local edits in-process via a fast stat index (`stat-index.json`) on the critical path (or defers the full `furrow` check and kept-branch upload to the background before swapping workspace files when the stat index is missing or stale), asks any local reader to retire concurrently at the keypress rather than in series, and when the view is already in hand from a listing (`RowsAt`, `RowsForSend`, `alt+c`, or `agents.open`), issues the open-state fetch and lease acquire concurrently from that view's head and fence (falling back to re-read, fetch, and acquire if the view was stale) so `OnShown` fires within 1–2 serial relay rounds (`open_gets=`, `open_rounds=`, `open_path=`).
- From the keypress until `shown`, Home's bottom line always shows `opening conversation… N KB` (updated every 500 ms). While a continue started from Home is running, text typed on Home is held as the arriving chat's draft and lands in its composer box when it opens; it is never sent automatically, and pressing Enter never starts a new conversation from it.
- Remaining frames, tool output stubs, job logs, task journals, and workspace files materialize in the background while the status line shows `files arriving · X of Y MB` (or `files arriving`, never `0 of 0`) and clears when done.
- Conversational turns run immediately against the arrived transcript. File, search, edit, shell, and git tools (`read`, `write`, `edit`, `multiedit`, `apply_patch`, `glob`, `grep`, `ls`, `bash`, and `!` user shell commands) as well as warm vault dotenv capture wait on `cell.WorkspaceArrival` and never read or run against a partial workspace tree.
- Transient relay or storage errors (`429`, `502`, `503`, `504`, `5xx`, timeouts, and connection resets) retry up to 3 times with backoff (`250ms`, `750ms`, `2s` plus jitter) per batch without discarding already-fetched frames. If the background workspace fetch still fails, the chat stays open, the status line shows `files couldn't arrive: <reason> · retry`, and workspace tools refuse with that reason until retry succeeds.
- `CODEAF_MOVE_FILES_FIRST=1` restores the previous files-before-open order and the `copying to this computer` counter on Home.
