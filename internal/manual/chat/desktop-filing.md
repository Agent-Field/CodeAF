# Dropping things into a place

## Drop a file, folder or link onto a place to add it as a source

In the desktop app, drag a file, a folder or a link onto a place's row in the rail, or onto a place on Home, and it becomes a source of that place. Every chat in the place can then use it. A file or folder is added by its location on your disk; a link must start with http or https. Dropping several adds each one, in the order you dropped them.

Holding Option does not change this: files and links are always added, never moved.

## Drop a tab onto a place to file its chat

Drag a tab onto a place to put that tab's chat in the place. The chat stays in any other places it is already in. Hold Option to move it out of the place you dragged it from instead. A tab that is not a saved chat, such as a settings tab or a chat you have not yet sent a message in, cannot be filed and nothing changes.

## When a dropped file is refused

A file dragged in from a browser window has no location on your disk, so codeaf cannot add it and says which item it skipped; the others in the same drop are still added. Use Add files or links on the place to choose it with the file chooser. If the engine refuses a source, the drop stops there and what was already added can be undone.

## Does codeaf offer to file a chat after its first reply

After a saved chat's first settled reply, the engine can offer an existing place. A matching folder is handled by the folder rule; otherwise the organiser weighs the chat against existing places and may ask the Chat filing model to resolve a close choice. A weak match stays in Now. An arrival never creates a place by itself; related chats in Now may earn a new-place offer on a later organizing pass.

"File chats without asking" is off by default. Turning it on allows eligible filings into existing places; new places, moves and merges still ask. A place you choose from the draft's suggested arrow is saved only after the first reply settles.

## What does moving a chat teach codeaf

Moving a saved chat by hand teaches the destination with that chat as an example. Only the chat you moved changes destination. After three corrections with a shared pattern, codeaf can propose a rule for future filing. A proposed rule waits for your approval; nearby chats do not silently move with your correction.
