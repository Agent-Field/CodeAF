# Latent-bug & divergence registry — algorithm wave 1

Policy (user decision 2026-07-27): the port is bug-for-bug; every suspected TS
bug is KEPT and logged here. After end-to-end parity is established, each
KEPT-BUG entry is a candidate for an A/B experiment on the bench issues —
fix on BOTH sides behind a flag, keep only measurable wins (beware
survivorship bias: swe-pro outperforms flagship harnesses WITH these quirks).

Entries marked KNOWN DIVERGENCE are places the Go port deliberately differs
(unreachable input domains, engine-specific text); each is bounded and
fixture-documented. PlanDB-phase entries are in PORT-ASSESSMENT.md §3.

## plandb guard closure

- KNOWN GO-ONLY FIX — The pinned TS guard leaves harness-created direct shell,
  verification, and mutation packages open, relying on a later model PlanDB
  `done` call and a lax descendant-exit path to mask the leak. The Go port
  closes guard-created shell packages deterministically when the tool returns
  and sweeps remaining harness bookkeeping or stale root-orchestrator claims
  during the root drain. Hardened exit otherwise turns every root-direct
  verification after an audit failure into a terminal stall; production run M
  demonstrated this with the leaked running task `t-xue4`.
- The same closure discipline covers the task tool's "Harness-created subagent
  task." bookkeeping packages: a failed dispatch closes a package this call
  created with an honest failure result (a reused open planner task is released
  instead, never auto-closed), the package is held as in-flight guard work for
  the whole dispatch so the drain sweep cannot race it, and the root drain
  sweep closes leaked subagent packages — including a composite parent left by
  a nested dispatch — exactly like the Direct packages. Production runs T and
  U both stalled on this family (`t-alx3`/`t-f18i`, `t-ko68`) before the fix.

## steploop tool settlement at stream end

- VERIFIED PARITY (was an accidental Go-only divergence) — In pinned TS the AI
  SDK executes tools inside `streamText`, so a provider stream cannot finish
  before a launched `execute()` resolves. The Go processor dispatches
  executors on goroutines, and its cleanup originally applied the 250 ms
  force-abort to every turn — silently writing "Tool execution aborted" over
  any tool that outlived the HTTP stream tail (run R carried 64 such parts;
  run T's audit subagents died of it). Cleanup now distinguishes the two
  populations processor.ts:634-656 actually drains: a DISPATCHED call waits
  unbounded on a healthy turn (the SDK-await equivalent) with the 250 ms grace
  once ctx is cancelled, while a registration whose tool-call part never
  arrived (length-truncated or errored stream — no executor exists to settle
  it) keeps the unconditional 250 ms drain TS itself relies on for that shape.
  An adversarial verification pass caught the first cut of this fix waiting
  unbounded on undispatched registrations, which deadlocked healthy turns;
  TestCleanupBoundsUndispatchedToolRegistrationOnHealthyTurn pins the split.
  Complete/FailToolCall also settle their call on persist errors now, since
  execute() discards those errors and an unsettled dispatched call would hang
  the drain.

## question tool

- KNOWN GO-ONLY FIX — Pinned TS enables the question tool for CLI clients
  (registry.ts:239-240) but nothing in a headless run answers `question.asked`:
  `Question.ask` awaits a Deferred nothing resolves (src/question/index.ts:155-179)
  and src/cli/cmd/run.ts never subscribes, so a model that asks a question
  hangs the run for unbounded wall-clock time. The codeaf runtime auto-rejects
  each ask through the service's own reject path, so the model receives the
  exact TS rejection ("The user dismissed this question") and the run keeps
  moving. The question service publishes on the same runtime-owned instance
  bus as durable session events and the stdout wildcard tap, so both
  `question.asked` and `question.rejected` are visible on stdout. To prevent a
  rejected ask from buying an unbounded sequence of paid retry turns, the
  third consecutive rejection in one session becomes a successful,
  model-visible terminal result instructing the model that answers are final
  and it must proceed with its best judgment. Any successful non-question tool
  call resets the counter. Embedded clients that attach a real answerer are
  unaffected — the auto-reject subscription lives only in the headless codeaf
  runtime, and answered questions never increment the bound. Contracts:
  `TestQuestionToolEventsReachStdoutInPinnedTypeScriptWireShape`,
  `TestHeadlessQuestionAutoRejectsInsteadOfHanging`, and the bounded-question
  tests in `internal/tool/question_test.go`.

## webfetch redirects

- KNOWN GO-ONLY FIX — Pinned TS asks permission for the initial webfetch URL
  and then lets its HTTP client follow redirects without re-checking the
  destination. Go keeps public-to-public redirects transparent and retains the
  default ten-hop cap, but blocks a redirect to loopback, RFC1918/ULA private,
  link-local, or cloud-metadata addresses when the originally approved host
  was public. An approved private origin may redirect within private space.
  The blocked destination is surfaced in the normal
  `Transport error (GET <url>)` fetch shape.

## web tool response metadata and retention

- KNOWN GO-ONLY FIX — Pinned TS reads the MCP websearch response text without
  a response-size cap. Go applies webfetch's 5 MiB declared/streaming limit to
  websearch as well, preventing an unbounded `ReadAll` while retaining the
  same error text as an oversized webfetch response.
- KNOWN GAP — Pinned TS calls `ctx.metadata` before websearch permission and
  provider execution, exposing intermediate title/provider metadata to live
  clients. Go has no intermediate tool-metadata streaming seam. It does retain
  the final provider metadata in `ToolResult.Metadata`, matching the TS final
  result, and now sends `model_name` to Parallel.
- KNOWN GO LIFECYCLE ADAPTATION — spilled full tool outputs use ascending
  `tool_` IDs and expire after seven days. TS starts a delayed hourly cleanup
  when its scoped truncation service starts; the Go registry has no matching
  service scope, so it performs the same age-based sweep during web-output
  handling and ignores cleanup failures.

## Go command surface

- VERIFIED PARITY — unavailable model tool calls already follow
  `src/tool/invalid.ts`: the steploop repairs the call to synthetic `invalid`,
  completes it successfully as `Invalid Tool` with `The arguments provided to
  the tool are invalid: ...`, and continues to the next model turn. The parser
  registers this fallback internally, sorts it with the callable definitions
  for TS-identical error text, and does not advertise it to the provider (the
  same split as TS `activeTools`). There is no second registry implementation
  because duplicating the existing fallback would change neither model-visible
  behavior nor control flow. Contract:
  `TestUnknownToolCompletesAsInvalidAndContinues`.

- KNOWN GO-ONLY DIVERGENCE — AgentField attribution is enabled by default.
  OpenRouter requests carry AgentField application headers, model system
  prompts tell commit-capable agents to add the SWE AF footer, and
  harness-produced commit/merge messages receive that footer directly. This
  deliberately mutates requests, prompts, and commit messages so AgentField
  usage and generated commits remain attributable across every Go execution
  path. Set `AGENTFIELD_OPENROUTER_ATTRIBUTION=0` to disable request headers;
  set `AGENTFIELD_COMMIT_ATTRIBUTION=0` to disable both the commit-prompt
  instruction and commit-message mutation (`false`, `no`, and `off` are also
  accepted for either variable).
- KNOWN GO-ONLY DIVERGENCE — shipped `codeaf run` and `codeaf resume` require a
  reachable AgentField control plane before pipeline work starts, whereas the
  TS CLI can run without one. The Go binary is an AgentField-integrated
  capability whose run DAG and status must be registered centrally; use
  `CODEAF_CP_URL`, then `AGENTFIELD_URL`, to select the plane. There is no
  disable flag for the shipped binary (injected in-process test backends are
  the only hermetic exemption).
- KNOWN GO-ONLY EXTENSION — CLI stdout includes the compact `stage`, `terminal`,
  and `supervisor` records consumed by `codeaf serve` and the AgentField
  control-plane projection. It now also exposes the TS-compatible
  `{id,type,properties}` instance-bus events; see `EVENTS-CONTRACT.md` for the
  complete, source-cited split between parity events and extensions.
- VERIFIED PARITY — `--format default` and `--format json` are the only accepted
  values, default to `json`, and produce the same NDJSON stream. The pinned TS
  command also never reads `args.format` after yargs validation.

## storage

- DELIBERATE SAFETY DIVERGENCE — `src/storage/storage.ts` writes JSON resources
  in place through `writeWithDirs`, so a process or host crash can leave a
  truncated resource. The Go durable layer uses a same-directory temporary
  file, file `fsync`, atomic rename, and directory `fsync`, with an advisory
  store lock covering cross-process read/modify/write. This is intentionally
  safer than TS because these files are the recovery authority. Contract:
  `TestStoreCrossProcessLockAndAtomicReplacementContract`.

## heftassign

- heftassign.go:303 (OrderByHeftStartBy) — KNOWN OUTPUT DIVERGENCE, NaN starts only. ## plandb readiness (src/db/schema.rs task_readiness via src/plandb)

- DELIBERATE DIVERGENCE (Go improvement, 2026-08-01) — TS/Rust readiness counts only `done`/`done_partial` upstreams as satisfying a `blocks`/`feeds_into` edge, so **cancelling** an upstream never unblocks its dependents, and `cancelTask` triggers no readiness recompute. The replan gate's documented no-op-leaf strategy is cancel-and-amend (replan prompt: cancelling "unblocks the remaining build"), which under TS semantics leaves every dependent pending forever; TS only survives because its dispatch-quiet exit slides into audit over an open graph — a hole this port closed (round 4). Two live runs (K, L) deadlocked terminally on exactly this: planner emitted a "Create go.mod" task for a file that already existed, the leaf correctly reported no work, every advisor correctly chose cancel-and-amend, and the graph stayed frozen. Go now counts `cancelled` in the satisfaction set and `CancelTask` runs the same `promoteReady()` sweep as `DoneTask`. `TestCancelledUnblocksDownstream` (formerly `TestParityCancelledDoesNotUnblockDownstream`) pins the divergence, including the exact run-L failed-then-cancelled shape. Composite auto-completion already counted cancelled children in both implementations and is unchanged.

## base contract check (src/session/base-contract-check.ts)

- DELIBERATE DIVERGENCE (Go improvement, 2026-08-04) — TS `planContractCopies` copies **every** registered contract path into the detached base worktree, on the assumption that `paths` holds only the files the check lives in (the registration prompt says `"paths": ["<file(s) the check lives in>"]`). Nothing enforces that, and a coder that also lists its **deliverable** turns the base check into a tautology: the file is copied in, the contract passes at base, `contract-cannot-fail` fires, the staleness judge rules the issue already fixed, and a real task is re-scoped to "report + regression test, no behavioral change". Observed end to end on issue #22 — goal "create hello.txt containing X", registered `{"command":"./test-hello.sh","paths":["test-hello.sh","hello.txt"]}` against a base commit holding only `README.md`; the run then deadlocked on `done-criteria evidence incomplete: unsatisfied criterion-2` against the re-scoped deliverable and burned its budget with the file already written. This is the same cascade `pinContractToWorktreeSources` already patches for the `pip install -e .` PYTHONPATH leak (werkzeug-3146), reached through a different door. Go therefore adds an optional `asserted_paths` field to the contract schema — the files the check asserts ABOUT — and `PlanContractCopies` never copies one, **including when the agent lists the same file in both arrays** (overlap resolves toward not copying, so a non-compliant agent fails safe). Excluded paths are noted to the run log. Because prompt compliance is probabilistic, the staleness prompt additionally receives, per copied file, whether it existed at the base commit, and is told that a copied file which did not exist at base and is the thing the issue asked to create is a mis-declared contract rather than evidence of staleness. `TestPlanContractCopiesExcludesAssertedPaths`, `TestPlanContractCopiesExcludesOverlapBetweenPathsAndAsserted` and `TestBaseContractCheckFailsWhenDeliverableIsAsserted` pin the behavior; `TestValidateContractWithoutAssertedPaths` pins that a pre-field `contract.json` still parses and behaves exactly as before (resume tolerance). **Upstream needs the same schema change before re-sync**: porting a newer `base-contract-check.ts` over this file would reintroduce the tautology.
