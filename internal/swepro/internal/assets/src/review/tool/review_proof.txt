Writes a per-finding proof file under `.review/lens/<lens>/proofs/<F>.md`
and auto-emits the matching verdict event to `.review/events.log`.
Used by Prover agents.

The verdict is captured as a structured field. The Synthesizer parses the
proof's frontmatter — no fragile prose-string parsing.

Three operations:

- `op: "open"` — start a proof file. Validates the verdict.
    Required: `finding_id`, `lens`,
              `verdict` (confirmed | refuted | inconclusive),
              `confidence` (0..1).
    Required if verdict=confirmed: `severity` (critical|high|medium|low|info).
    Writes the frontmatter (verdict, confidence, severity) and a header.
    You CANNOT change the verdict after open — pick it deliberately.

- `op: "section"` — append a labeled body section.
    Required: `finding_id`, `lens`, `section`, `content`.
    `section` must be one of: summary, evidence, reasoning, repro,
    suggested_fix. Append `## <SECTION>\n\n<content>\n`. Call this 3-5 times
    to build the full proof — one call per section keeps each tool call
    small.

- `op: "close"` — finalize and emit the event.
    Required: `finding_id`, `lens`.
    Validates: summary always required; if verdict=confirmed → repro AND
    suggested_fix MUST be present. Emits the matching event:
      verdict=confirmed → `finding-confirmed` event
      verdict=refuted → `finding-refuted` event
      verdict=inconclusive → `finding-inconclusive` event
    With cause "prover close" and all relevant fields. Returns a one-line
    summary for the parent Investigator.

Confirmed verdicts require a concrete failing scenario (repro) and a fix
suggestion. Prose-only confirmations are rejected at close.
