Writes `.review/lens/<lens>/confirmed.md` — the per-lens rollup of confirmed
findings. The Synthesizer reads these files to compile the final report.
Used by Lens Investigator agents (after all their Provers return).

Three operations:

- `op: "open"` — start the rollup file with summary counts.
    Required: `lens`, `candidate_count`, `confirmed_count`,
              `inconclusive_count`.
    Writes a header and a totals block. Call this once after all Provers
    have returned.

- `op: "finding"` — append one confirmed finding section.
    Required: `lens`, `finding_id`, `title`, `file`, `severity`,
              `confidence`, `why`, `repro_summary`, `fix_summary`.
    Optional: `line`.
    Appends a structured block with location, severity, confidence, the
    one-paragraph why, a short repro summary, and a short fix summary.
    Each call adds one finding — keep them small.

- `op: "close"` — finalize. Emits a `lens-saturated` event to events.log
    with the lens name and the candidate/confirmed counts captured at open.
    Required: `lens`.

Only `confirmed` verdicts go into the rollup. Refuted findings live in
proofs/ for audit trail. Inconclusive findings get listed in an appendix
section if you want — call `finding` with the inconclusive ID and add an
"Inconclusive" label in the title prefix — but the recommended pattern is
to only include confirmed findings here.
