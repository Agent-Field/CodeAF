# Web tab: open design questions

Questions the web lane met while building the native web tab (design Shell 3d,
3j, 3k; Components "Link chip"; Interactions). Each one ships with the
conservative assumption stated, so nothing waits on an answer. These will be
consolidated into the design ledger.

| # | Question | Assumption shipped |
|---|---|---|
| W1 | Every app surface over a page (menu, hover card, tooltip, dialog, palette, overview, toast) is drawn under a native view, so the view hides while one overlaps its sheet. Tooltips of the web header's own buttons drop into the sheet, so hovering Back for 500ms hides the page until the tooltip goes. Should the header's tooltips open above, or should the page stay and the tooltip be dropped? | The rule is uniform: anything overlapping hides the page, and the last picture of the page stands in while it is hidden. No tooltip is suppressed. |
| W2 | The tab glyph's monogram was the first letter of the tab title, which for a web tab becomes the page title ("j" for "json package"). The design's address field and tab both show the site's letter. | Settled in integration: `Tab`, `SplitTab` and `TabGlyph` take a `monogram` and `TabItem` passes the site of the pane's address (`monogramOf`). The tab and the address field now show the same letter and it does not change as the title loads. |
| W3 | Favicons. Design 3j: "the real favicon if the engine fetched the site, else a monogram". A web tab's own page has a favicon the view knows, but Tauri exposes none and the engine never fetched the site. | Monogram only. No favicon is fetched by the renderer or the native side. |
| W4 | Load progress. The 2px line can show a fraction. WebKitGTK reports `estimated-load-progress`; WKWebView only through KVO. | The line runs as the indeterminate sweep while loading, on both platforms. |
| W5 | A refused download, popup or permission request needs one muted line. The sheet is under the native view, so a line there is invisible. | The line replaces the dimmed path inside the address field for one state update (`role="status"`). |
| W6 | Where does "Start a conversation with this page" put the page? | A new conversation tab opens with an unsent draft naming the page's title and address, and the native snapshot of the page offered to that tab's composer as `page.png`. Nothing is sent and no model is called until the person sends. The button is absent when the workspace has not registered a host. Integrated: the workspace registers the host; the composer attaches `page.png` once (a tab switch does not re-attach it, and the tray itself is not persisted, as for any attachment). |
| W7 | Cookies and logins. Should web tabs share one persistent store, be private, or follow a place? | One persistent store for all web tabs, apart from the app's own (`web-tabs` data directory on Linux; a fixed data-store identifier on macOS 14+, the default store before 14). |
| W8 | Keyboard: ⌘L / Ctrl+L for the address, ⌘R reload, ⌘[ ⌘] history. While the page has focus the keys go to the native view, never to the app. | Not bound yet; the controls are reachable by Tab and Enter/Space. Shortcut labels belong in `design/keyboard.ts` (rail and keys lane). |
| W9 | Find in page. | Not built yet. Both platforms can find without giving the page view IPC. The command is `web_find { pane, query, forward }` → `{ found, matches? }`, with no current index, in DECISIONS.md (`t-d5-tab-web-find-research`) and Open row TW-14. Follow-up: `t-d5-nat-web-find`. Supersedes the note that Tauri 2.12 exposes no find. |
| W10 | A page's `window.open` or `target=_blank`. | A typed `web://new-tab` request: the workspace opens a web tab in front; without a workspace host the link goes to the default browser, as a link chip's click does. A page never gets a window. |
| W11 | Hover and overview cards for web tabs are the one kind with a picture (3k). | Settled in integration: the shared `PreviewShot` is the web card in both places (the overview draws its body only, so there is one title and no second frame). The picture is the native snapshot, taken while the card is shown and at most every 3 s; with none, the shot area says why ("No picture yet", "No picture of this page here", "Pages open in the desktop app"). The lane's own `WebPreview` and its CSS were removed. |
| W12 | Which gesture opens a link as a web tab? | Command-click on a Mac, Control-click elsewhere, on a link chip or text link, when the workspace has a web host and the address passes the web policy. The tab opens in front (a page's own new window does too). Plain click still opens the default browser. Shift, Alt and middle clicks keep the browser's behaviour. |
| W13 | A typed address in the new-tab field: page or question? | Both, page first. An address (`pkg.go.dev/x`, `https://…`, `localhost:3000`) puts "Open … in a web tab" as the first row, and the conversation row stays second so a URL that is a question is one arrow away. The hint beside the field follows the highlighted row. |
| W14 | A web tab moved to another window. | The page reloads there: a native view cannot change windows, so the new window's open replaces the old window's view. History of that page is lost on a move. |
| W15 | Closing a web tab, then reopening it from the closed list. | The native view closes with the tab (its page and history go); the reopened tab loads its saved address afresh. |
| W16 | Link chips and the web address field both show a site monogram, with different hue sources (the chip hashes the registrable domain, the tab hashes the full host). | Left as built. One hue source for both would need the shared monogram helper to take the registrable domain. |
